# Development Guidelines

## Code Architecture

- **MCP Integration**: Always utilize MCP (Model Context Protocol) tools and resources first before implementing custom logic. Check available MCP servers for existing solutions.
- **Cross-Platform Consistency**: The application targets three platforms — Electron (GUI), CLI, and Android (Capacitor). All core business logic in `src/js/` must be shared; only the platform shell (entry points, transport, storage adapter) is platform-specific.
- **Entry points**: Electron `src/js/index.ts` (bundled by `scripts/build-main.ts` into `out/main/app.js`, with a source map, behind the `out/main/index.js` loader that package.json `main` points at — `pnpm start`/`dev` build it first; `out/` stays out of `dist/`, Capacitor's webDir) · CLI `src/js/cli/cli.ts` · Electron preload `src/js/preload.ts` · Capacitor bridge `src/js/bridge/capacitor.ts`. The same React renderer (`src/js/react/`) runs under both Electron and Capacitor.
- **API surface swap**: `src/js/apiFactory.ts` selects real vs mock implementations at runtime based on `settings.mock`. All callers go through the factory — do not import `src/js/api/*`, `src/js/strategies/*` or `src/js/mock/*` directly from business logic. `src/js/api/` is the transport layer (api-client + endpoint wrappers, no `services/` imports); the real-mode composition over it (voting pass with join/claim pre-steps, entry-picking boost, title-pinned challenge read) lives in `src/js/strategies/real/`, the mock counterpart in `src/js/mock/` (`strategy.ts` over the `endpoints/*` fakes, assembled into `mockApiClient` behind the `mock/index.ts` facade).
- **IPC** (deep reference: `docs/architecture.md`): `src/js/ipc/manifest.ts` is the dependency-free single source of truth for the `window.api` surface; both shells generate from it and CI enforces name-parity. Signatures travel through the `WindowApi` type (`src/js/types/ipc.d.ts`, derived from the manifest + every `buildHandlers()`): a renderer call in a type-checked file is checked against its handler's parameters and result — only as precise as that handler's type annotations. Handlers export `buildHandlers(deps)` + `register(ipcMain)`, are reused by CLI and Capacitor (no parallel impls), and **return `{success,error}` — never throw to the renderer**.
- **Persistence**: use `createJsonStore()` (`src/js/settings/storage.ts`) for platform-aware JSON; don't hand-roll `fs`. Node-side platform detection = `src/js/runtime.ts`; renderer-side = `globalThis.Capacitor?.isNativePlatform?.()`. Paths to the app's own files (HTML, preload bundle, assets, the dev model cache) come from `appPath(...)` (`src/js/appPaths.ts`) — never a module's own `__dirname`, which is the bundle's directory once the main process is bundled.

## Application Domain & Invariants

> Deep reference: **`docs/architecture.md`** (and `docs/scheduling.md` for the timer engines). These are invariants an edit must not violate.

- **Voting pass**: one shared loop `runVotingPass` (`src/js/services/votingOrchestrator.ts`) for real+mock — never fork it; inject differences via `deps`. The per-challenge runners are **sequential, never parallelised** (shared challenge-object mutation). Rule precedence in `_runVotingRules` (`src/js/services/decisions/ruleEngine.ts`, exported through the `services/VotingLogic.ts` facade) is load-bearing.
- **Two distinct sentinels — don't merge them**: for `exposureTarget`/`lastHourExposureTarget`, `0`/null = "target == trigger" (rule **stays active**); for `boostTime`/`emergencyFill`/`keyUnlockedBoostTime`, `0` = feature **off**.
- **Scheduler**: single recursive `setTimeout` chain, no cron; one decision point `computeNextCycleDelayMs`; invariant "never sleep past a boundary"; cancellation is a global flag that propagates by `return`, never `throw`.
- **API transport**: everything POSTs through `makePostRequest` (`src/js/api/api-client.ts`), which returns the body or **`null` — it never throws**. Branch on `null`; keep retry/backoff centralised; custom (Android) adapters must call `finalizeAdapterResponse`.
- **Semantic lexicon** ranks auto-fill photos only — **never** the vote decision; `SEMANTIC_MATCH_FLOOR` is build-gated by `scripts/validate-lexicon.ts`, not hand-tuned.
- **Safety**: optional-chain every per-challenge API read (an unguarded throw aborts the whole pass); new-entry detection compares ids as **sets, not positions**; mock mode must pass `cleanupStaleMetadata: null` so it never touches the real `metadata.json`.
- **Scenarios** (`docs/architecture.md` §11): a phase's settings overlay sits above every layer of `getEffectiveSetting`; unreadable scenario state halts the challenge (never a silent restart); the runner re-reads live state before each action and persists progress after each one, so a resumed rule never repeats a landed spend.
- **Security invariants** (details/limits in `docs/architecture.md` §10): keep `contextIsolation` on, `nodeIntegration` off, and the sandboxed-preload / `window.api`-only exposure — regressing any is a severe-vuln class; keep the `isTrustedSender` frame check on every invoke; never log a raw headers/token object (redaction is key-allowlisted, not exhaustive — it only guards the key names it lists).

## Testing Standards

- **Test Organization**: All test files must be placed in the `tests/` directory following proper Jest conventions and structure.
- **Mock Configuration**: Never use `mock: false` in any Jest or testing commands - use proper mocking strategies instead.
- **Mocking ES modules**: `src/` is `import`/`export`, compiled for Jest by swc with its standard interop. Two consequences:
    - A real module's exports are non-configurable getters, so `jest.spyOn` / property assignment on it throws ("Cannot redefine property"). To spy on a real module (or a Node builtin such as `node:fs`), give it a partial mock first: `jest.mock(p, () => ({ __esModule: true, ...jest.requireActual(p) }))`. For a builtin that packages default-import (fs), also pass `default: <the real module>`.
    - `import * as x` of a factory mock _without_ `__esModule` gets a copy of the factory object, so a test that later replaces a property on the mock (`mod.fn = jest.fn()`, `jest.spyOn(mod, …)`) or compares identity is not seen by the code under test. Put `__esModule: true` in any factory whose properties a test replaces. Changing a `jest.fn()` in place (`.mockReturnValue`, `.mockImplementation`) works either way.
- **100% coverage gate**: CI fails on anything below 100% — Jest via `coverageThreshold` (all four metrics over `src/js/**` **and** `scripts/**`, `pnpm test:coverage`; `tests/helpers/swc-transformer.cts` wraps @swc/jest so swc's generated `export` getters don't count as statements), Android via `./gradlew jacocoTestCoverageVerification` (zero missed on every JaCoCo counter). New code ships with tests; `istanbul ignore` is only for branches genuinely unreachable under Jest, with a comment saying why. Scripts gate their CLI entry with `runIfMain(require.main, module, main)` (`scripts/lib/run-if-main.ts`), never an inline `require.main === module` — that branch can't run under Jest.

## UI/UX Standards

- **Styling Framework**: GUI application uses Tailwind CSS + DaisyUI for all styling components
- **Custom CSS Policy**: No custom CSS is allowed except for the predefined Latvian color theme (already defined in the project)
- **Component Consistency**: Follow DaisyUI component patterns and conventions for consistent user experience

## Renderer / UI

> Scope: `## UI/UX Standards` above governs styling policy (Tailwind/DaisyUI/theme); this section governs component & data-flow conventions. Deep reference: `docs/architecture.md` §8–9.

- **Backend access**: all backend calls go through `window.api.*` via `src/js/react/api/` only — `useIpcQuery.ts` / `useAsyncIpcAction.ts` for queries and actions, `ipc.ts` for one-shot calls, event subscriptions and best-effort logging (`logRendererError`) — **no per-platform branching in components**. Oxlint rejects `window.api` / `globalThis.api` access anywhere else under `src/js/react/`.
- **Structure**: no router (mount entry points `mountApp`/`mountLogin`); no toast lib — inline DaisyUI `alert` + `ui/ErrorBoundary`. User-facing error text follows _what happened → why → what next_, translated, never raw status codes at the user.
- **Primitives & theme**: reuse `src/js/react/components/ui/` primitives; new modals **must** use `ui/Modal.tsx` (owns the a11y focus-trap bar). Theme = DaisyUI `data-theme`, no `dark:` variant. High-frequency ticks via `@preact/signals` (`useTimers`) to avoid re-rendering the challenge list.
- **i18n mandatory**: user-facing strings via `useTranslation().t()`, added to **both** `src/js/translations/english.ts` and `latvian.ts`. Internal/log strings stay English.

## Code Quality

- **DRY Principle**: Prioritize code reuse over duplication. Extract common functionality into shared utilities, hooks, or components
- **Shared Logic**: Create reusable functions and modules that can be utilized across both Electron and CLI implementations

## Configuration Management

- **Settings Architecture**: Settings facade lives at `src/js/settings.ts`. Schema (keys + defaults + validation) is in `src/js/settings/schema.ts`; persistence transport (fs on Electron/CLI, `@capacitor/preferences` on Android) is in `src/js/settings/storage.ts`. The facade's internals (load/merge/migrate/save in `settings/persistence.ts` + `settings/migrations.ts`, overrides, title rules, profiles, title pins, reset) live in sibling modules under `src/js/settings/` and are private to it — Oxlint rejects importing them from outside that directory. Always go through the facade. `loadSettings` validates what it reads (`dropInvalidValues` in `settings/persistence.ts`): a top-level value of the wrong type, a `challengeSettings` container of the wrong kind, or a schema value its zod validation rejects is dropped for the default and logged once — so a setting read returns what its type says. Don't re-guard setting values downstream; widen the load-time check instead.
- **Environment Variables**: Do not use environment variables (.env files) for application configuration - use the established settings logic instead
- **Configuration Consistency**: Ensure settings are accessible and consistent between GUI and CLI interfaces

## Key Commands

> Package manager: **pnpm 12+** (pinned via `packageManager` in `package.json`, bootstrap with `corepack enable`). Use `pnpm <script>` everywhere — the `npm` CLI is not supported.

- **Dev (GUI + watchers)**: `pnpm dev` — runs CSS, React, main-process bundle and Electron (electronmon) watchers concurrently; a core edit rebuilds `out/main/app.js` and electronmon restarts the app
- **CLI**: `pnpm cli:start` · `cli:vote` · `cli:status` · `cli:login` · `cli:help`
- **Running TypeScript under Node**: every npm script that runs `src/` or `scripts/` code (`cli:*`, `settings:*`, `build:*`, `size*`, the lexicon and readme scripts, …) runs as `node --import tsx scripts/….ts`; tsx compiles the ESM-syntax TypeScript to CommonJS for this `"type": "commonjs"` package, so `require.main`, `module` and `__dirname` keep working. A new script gets the same prefix. The two files Node loads by itself — electron-builder's `afterPack` hook and Oxlint's `jsPlugins` rule — are `.mts` (ESM TypeScript Node strips natively), so they use no CommonJS globals.
- **Build**: `pnpm build:mac` · `build:win` · `build:linux` · `build:android` · `build:cli:all`. Each has a `:lite` twin (`build:mac:lite`, `build:cli:mac:lite`, `build:android:lite`, …) that leaves the local vision model and its runtime out — see `docs/architecture.md` §4a.
- **CLI build prereq**: needs `tar` and network access on first build (the pinned SigLIP model is fetched into `.cache/vision-model` by `scripts/fetch-vision-model.ts`), plus, on macOS, `codesign` (Xcode CLT). The binary is deliberately NOT stripped: the embedded vision runtime's native addons (onnxruntime-node, sharp) need Node's exported N-API symbols. Each CLI target is built on its native-arch runner — mac on `macos-26`, linux x64 on `ubuntu-latest`, linux arm64 on `ubuntu-24.04-arm` (separate `build-cli-arm` job). Local cross-arch builds (e.g. `build:cli:linux-arm` from an x64 host) aren't supported by the script — run on matching hardware or let CI handle it. UPX is intentionally NOT used — macOS AMFI rejects packed Mach-O, and postject's ELF section injection trips UPX's `bad e_phoff` structural check on Linux. Mac CLI binary is ad-hoc signed by the build — no Developer ID / notarization, so browser-downloaded copies still hit Gatekeeper and need `xattr -d com.apple.quarantine`.
- **Settings (dev)**: `pnpm settings:get` · `settings:set <key> <value>` · `settings:schema` · `settings:reset`
- **Tests**: `pnpm test` (full suite) · `pnpm test:watch` · `pnpm test:coverage` — Jest has two projects (`node` and `happy-dom`); React tests are `.test.tsx` under `tests/react/`, everything else is `.test.ts`
- **Lint/format/types**: `pnpm lint` (Oxlint over `src/`, `scripts/`, `tests/`) · `lint:fix` · `format` (Prettier) · `typecheck` (`tsc --noEmit` over the app and `tests/` programs, checker-only — see **Dependencies & Type Checking**)
- **Code hygiene**: `pnpm knip` (unused files/deps/types — config in `knip.json`; the `exports`/`nsExports` rules are off: what they still flag are test hooks — exports only tests read, through a `require()`d module object knip can't trace) · `pnpm size` (renderer bundle brotli **delta** gate — `scripts/check-size-delta.ts` compares each bundle's brotli size against committed `.size-baseline.json` and fails only when one grows more than a threshold (default 5 kB, override `SIZE_DELTA_KB`) since the baseline; it catches an accidental heavy import — e.g. something newly reachable from `App.tsx` pulling in `settings/schema.ts`, whose zod import adds ~60 kB brotlied that tree-shaking does not remove, which is why size-relevant bounds live in the dependency-free `settings/limits.ts` — while letting a few kB of real feature growth through. On intentional growth run `pnpm size:update` and commit the refreshed baseline) · `pnpm size:cli` (coarse SEA binary / `cli-bundled.js` size guard, `scripts/check-cli-size.ts`)
- **README version sync**: `pnpm verify:readme` ensures README version strings match `package.json`. `pnpm update:readme` rewrites them. The release workflow enforces this — drift will fail CI.
- **Semantic lexicon**: `pnpm fetch:embeddings` (manual, network — downloads the pinned GloVe archive once into gitignored `scripts/.cache/`, then prunes/quantizes it into the committed `scripts/lexicon-embeddings.json`; MUST be re-run after editing `scripts/lexicon-concepts.json`, offline once cached) · `pnpm build:lexicon` (offline, deterministic — intermediate → `src/assets/semantic-vectors.json`; CI diffs the output) · `pnpm verify:lexicon` (statistical gate for `SEMANTIC_MATCH_FLOOR`)

## Dependencies & Type Checking

- **Off-`latest` pins are intentional** (registry-verified 2026-08-09): `prettier` is a true pre-release (`4.0.0-alpha`, published under `next`); `electron-builder` follows the **`v26` dist-tag**, which carries 26.15.x patches AHEAD of the stale `latest` tag (upstream stopped moving `latest` at 26.15.3). `electron-updater` sits exactly on `latest`. Do **not** "downgrade" any of these to `latest`, and don't merge a bot PR that does. Everything else stays on the exact latest stable.
- **The `v26`-tag blind spot**: `pnpm outdated`, `npm-check-updates`, and Dependabot all compare against the `latest` dist-tag only — patches (or a future CVE fix) published under `v26` are invisible to the whole update pipeline. Check `npm view electron-builder dist-tags` manually when bumping deps.
- **Automated updates**: Dependabot (`.github/dependabot.yml`) opens weekly PRs for npm + github-actions; majors (incl. `github/codeql-action`) land as individual PRs. It never downgrades and only offers pre-release bumps for deps already on a pre-release, so the pins above are preserved. The manual `pnpm bump` (npm-check-updates) still works for ad-hoc bumps.
- **CVE overrides**: `pnpm-workspace.yaml` carries an exact-pinned `overrides:` block for dev-tree-only advisories whose upstream chains hard-pin vulnerable versions (currently uuid, pinned by xcode). Re-check with a full `pnpm audit` after lockfile changes; drop an override once upstream moves past the vulnerable range.
- **Build-script approval**: pnpm 12 requires opting each native postinstall script into `allowBuilds:` in `pnpm-workspace.yaml`. Keep that list minimal — every entry is an arbitrary-code-execution opportunity.
- **Type checking** (`pnpm typecheck` → `tsc --noEmit`, TypeScript 7's native compiler): `src/js` is TypeScript (`.ts`, `.tsx` for JSX) and `tsc` is a **checker only, never a compiler** (`tsconfig.json` sets `noEmit`): esbuild bundles the sources, swc compiles them for Jest, and `node --import tsx` runs them for the CLI and scripts. One program with bundler resolution and DOM + Node typings covers the core and the `.tsx` renderer; every file is strictly checked, the program has zero errors, and new code ships typed. CI gates on it. `scripts/` is in the program too; `tests/` is its own program (`tests/tsconfig.json`, the same strict settings plus Jest's globals, which stay out of `src/js`), run by the same `pnpm typecheck`. A test keeps each `require()` where it is, because mocks and globals are set up before the module under test loads, and types it where it is produced: `require('…') as typeof M` (with `import type * as M`), or `jest.mocked(require('…') as typeof M)` for a mocked module. A mock names the function it stands in for — `jest.fn<R, [Args]>()`, `jest.MockedFunction<typeof fn>` — never a bare `jest.Mock` (that is `Mock<any, any>`; `tests/ci-validation.test.ts` rejects it); `tests/jest-matchers.d.ts` types the asymmetric matchers, which `@types/jest` leaves `any`. A deliberately wrong-typed input or partial fixture goes through `invalid<T>(…)` (`tests/helpers/invalid.ts`), never `as unknown as T`. In `.tsx`, write an unconstrained generic arrow as `<T,>(…) =>` so it is not read as JSX. Shared shapes: the GuruShots API payloads (`Challenge`, `RankingEntry`, `VoteImagesResponse`, …) live in the type-only `src/js/types/gurushots.d.ts`, and `settings/schema.ts` exports `SettingKey` + `SettingValues` (each setting's value type, read off its zod validator) — pull them in with `import type { Challenge } from '../types/gurushots'` rather than re-declaring a shape. Give React state, refs and contexts their type as a type argument (`useState<X | null>(null)`, `createContext<X | null>(null)`) and a typed `useCallback` handler as `useCallback<H>((…) => …, deps)`, not a cast on the initial value. Prefer precise types: a function declares the type it needs and its callers must pass it — don't widen a parameter to `unknown` to make a loose caller compile. GuruShots responses are typed shapes with optional/nullable fields, never `unknown`. IPC handler parameters carry the type the renderer must send (that is what checks `window.api` calls) and still validate at runtime, because the CLI and a compromised window can send anything. `unknown` is only for values with no fixed type: validators/sanitizers whose job is the check, persisted JSON and user-authored documents before validation, caught errors, and the logger's payload. No `any` anywhere, written or leaked — lint-enforced (see **Linting**). The IPC handler map's `IpcHandler` takes `never[]` (every handler's own parameter list is assignable to it), and `invokeHandler` (`src/js/ipc/registerHandlers.ts`) is the one place renderer arguments are passed to a handler, each of which validates its own at runtime. No `@ts-ignore` / `@ts-expect-error` / `@ts-nocheck`.
- **Linting** (`pnpm lint` → Oxlint, config in `.oxlintrc.json`): one Rust linter for `src/`, `scripts/` and `tests/`, `.ts`/`.tsx`/`.mts`/`.cts` alike, with its own parser, so the TypeScript version doesn't matter to it. The config mirrors `eslint:recommended` (categories off, rules listed; Oxlint lacks only `no-dupe-args` and `no-octal`, both syntax errors in the strict `src/js` modules), `no-console` / `no-unused-vars` (`_`-prefixed args and catch bindings allowed), `no-undef` off everywhere tsc checks (tsc resolves every identifier, type queries included), the React hooks rules and jsx-a11y's recommended set (without `control-has-associated-label`'s `includeRoles`, which Oxlint doesn't support) for `src/js/react/`, the renderer-boundary and settings-facade `no-restricted-imports`, and the `window.api` `no-restricted-properties`. Type-aware promise rules (`typescript/no-floating-promises`, `no-misused-promises`, `await-thenable`) run over `src/js` through `oxlint-tsgolint`, which bundles its own typescript-go and ignores the installed `typescript`. `typescript/no-explicit-any` and the type-aware `no-unsafe-*` rules (argument, assignment, call, member-access, return) run over `src/`, `scripts/` and `tests/`: an untyped value is typed before it is used — a lazy require as `require('m') as typeof import('m')`, parsed JSON as `const x: unknown = JSON.parse(…)` narrowed with `isPlainObject` (`src/js/plainObject.ts`) / `isInteger` (`src/js/numbers.ts`) or a type predicate. `src/js/types/globals.d.ts` narrows `Array.isArray` to `unknown[]` (the standard `any[]` would erase a typed array's element type and leak `any`). `scripts/lint/a11y-local.mts` is a local JS plugin (`jsPlugins`, ESLint rule API) for the one check no built-in rule covers: every `<label>` names or wraps its control. `oxlint-disable` / `eslint-disable` comments both work. On `void`: it satisfies `no-floating-promises` without handling anything — pair it with `.catch`/try-catch wherever the rejection matters; bare `void` only for inconsequential fire-and-forget calls. Oxlint enables no formatting rules, so Prettier owns formatting. Dependabot bumps `oxlint` and `oxlint-tsgolint` together (`oxlint-toolchain` group). Supply-chain note: devDependencies are outside the blocking `pnpm audit --prod` gate (a non-blocking full audit step surfaces dev-tree CVEs).
- **Repository analysis**: Ripwire is the supported structural-analysis backend for the shared core, `.tsx`, tests, scripts, and whole-repository queries. Use its MCP tools or the pinned `ripwire` CLI workflow appropriate to the question; use `tsc` for compiler-exact type diagnostics.
- **Pre-commit hooks**: `lefthook` (`lefthook.yml`, installed by the `prepare` script) runs `oxlint --fix` + `prettier --write` on staged files only, and re-stages what it fixes (`stage_fixed`) so the fix lands in the same commit — note this re-stages whole files, not partial `git add -p` hunks. Full tests stay in CI. An `--ignore-scripts` install skips hook setup; run `pnpm exec lefthook install` manually if so.
- **CI security gate**: `pnpm audit --prod --audit-level=high` (shipped deps only) runs in the test workflow; CodeQL (`.github/workflows/codeql.yml`) scans on push/PR and weekly.
- **CI hygiene gates**: the test workflow runs `pnpm size` (renderer bundle budgets) on the main `ubuntu-slim` job and `pnpm knip` (dead code / unused deps) in a separate `knip` job on `ubuntu-latest` — knip's oxc parser allocates a ~2 GiB ArrayBuffer that the slim runner can't satisfy. `pnpm typecheck` runs in its own `typecheck` job on `ubuntu-latest`, so a type error reads as its own red check. Each CLI build job runs `pnpm size:cli`.

## Git Operations

- **Push Restrictions**: Never push changes to remote repositories under any circumstances. All git operations must remain local only.
- **Commit Policy**: Adding commits and performing git read operations (status, log, diff, etc.) are permitted and encouraged for development workflow.
- **File Reset Prohibition**: Never use `git checkout` to reset or revert files under any circumstances. This includes avoiding commands like `git checkout -- <file>` or `git checkout HEAD <file>`.
- **Branch Operations**: Local branch operations are allowed, but all changes must remain in the local repository.
- **Safe Git Commands**: Stick to read-only git commands (status, log, diff, show) and local commit operations only.

## Development Commands

- **Linting & types**: Run `pnpm lint` and `pnpm typecheck` after code changes. `src/js` is TypeScript — `tsc` runs as a checker only (strict over `src/js`), and Oxlint lints `src/`, `scripts/` and `tests/`; see **Dependencies & Type Checking**.

- **Testing Completion**: All tests must pass regardless of code changes (even if they are not related to the code being changed)
